yoyo-app — MVP Architecture

Two pipelines, one product: an offline pipeline that learns tricks from real tutorials, and an on-device pipeline that watches you throw.

Why this shape

  • • Splits the problem in two: learning tricks (offline, cheap, already solved) vs. seeing you throw (real-time, hard, unsolved).
  • • Everything on-device: no video upload, no per-frame cloud cost, low latency, GDPR-safe.
  • • The KB is the moat — a dataset of tricks written as machine-checkable rules, not just videos.

The hard part, honestly

  • • Body/hand pose is off-the-shelf. Detecting the yoyo and the string path is not.
  • • Yoyo "form" ≈ string configuration, not body angles — so v1 asks "did it land?", not "is your posture perfect?"
  • • Skateboard-trick classification research hit only 36% accuracy on limited data. Your dataset is the moat.

Build order for v1

  • • 1. One trick (Trapeze), one angle, one question: landed or not?
  • • 2. Film 50–100 attempts → label → train the yoyo/string detector.
  • • 3. Wire coach_signals → on-screen "you failed at step N".
  • • 4. Add scoring, then styles 2A–5A (much harder).
